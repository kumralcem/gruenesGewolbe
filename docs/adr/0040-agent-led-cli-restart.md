# Restart Around an Agent-Led CLI

The replacement starts with a small CLI in which an agent visits supplied source links, determines what to preserve, categorizes saved items, and writes their descriptive records. The user chose this direction because the existing programmatic capture approach is too restrictive for the material they want to save; the durable archive should retain ordinary files, a shallow item layout, and a Markdown item record alongside each saved item's content, without a database.

Capture intent is explicit in commands such as `gg painting <url>` and `gg idea <url>`, so the agent does not have to infer whether the user wants the artwork or the ideas on a mixed-content page. Painting capture preserves the artwork and descriptive metadata, excluding surrounding discussion by default. Shared operations beneath the CLI will also support a later private hosted browser interface; see [ADR-0044](0044-private-hosted-interface-over-file-vault.md).

The initial CLI runs captures in the foreground with progress, and must accept multiple inputs in one invocation. This supports pasting a set of links without requiring a background job system. Each entry remains a separate capture with an individual outcome, including a queued decision when necessary. Input syntax, processing concurrency, and interrupted-batch recovery still need to be specified; the capture operations should also be usable by the later GUI.

The agent may use ordinary command-line tools and write and execute short scripts within its sandbox to handle varied source material. This does not grant host shell access, provider credentials, or unrestricted writes to the live vault. [ADR-0043](0043-isolated-agent-with-trusted-controller.md) records the accepted controller/worker separation; its implementation remains to be prototyped.

Source access is public and unauthenticated in the first version. Do not require website logins, store website credentials, or reuse authenticated browser profiles or imported login cookies. This restriction concerns source websites; the user-configured OpenAI or OpenRouter API key is still required for model access. If a source is inaccessible, report the URL and reason and continue processing the remaining entries. Do not create an incomplete saved item or Capture Queue entry for that failure. Public browsing and extraction still need testing in the standalone CLI.

Painting capture includes searching beyond the supplied page for a better image and reliable identification when useful. The user wants this research within the normal capture workflow because implementing the same behavior as fixed extraction rules proved impractical; research limits and stopping criteria remain to be settled through representative captures. Unknown identity does not block saving: preserve the image, leave uncertain facts explicitly unresolved, and report the gaps. This reopens the image-search deferral in [ADR-0016](0016-basic-paintings-import-before-image-search.md) for URL capture, without deciding the separate local-file import workflow.

The visual workflow has since broadened to include photography and sculpture, with agent-selected home subvaults; see [ADR-0041](0041-agent-classified-visual-capture.md). `gg painting` is the initial command example, and its final name remains open.

`gg idea` accepts direct articles, news stories, posts, and YouTube videos as sources. The Summary is its most important result, backed by readable source text or an existing video transcript and source links; for a post pointing to an article, the user generally wants both texts in one Idea Source. Summaries make ideas findable by remembered problems and concepts. For instructional or advice material, preserve the instructions themselves with the conditions and details needed to follow them, removing narrative rather than reducing actionable steps to a vague recap. An optional capture instruction can focus the summary on the user's concern; capture must also work without it. Replies are excluded unless explicitly requested. When no usable transcript is available for a video, skip the request and notify the user, without creating an item, queue entry, or audio-transcription workflow.

Rediscovery includes both `gg search` and a required `gg ask` command. The user can describe a topic or problem in ordinary language and have the agent return the relevant saved files, including material using different wording. Search must work without requiring the user to edit existing records or curate search terms. Retrieval leaves saved files unchanged. A bounded local search tool underneath the agent is the proposed implementation, with matching quality still to be evaluated on real queries.

Source age must be visible for time-sensitive instructions: retain the Source Publication Date when known, separately from the Capture Date. Visible dates are sufficient for the first version. Rechecking, last-checked tracking, active updating, and automatic expiry are outside the requested workflow.

Provider access must be configurable from the outset for OpenAI and OpenRouter, with a small CLI settings wizard for provider, model identifier, and credentials. Model identifiers are user configuration, without a hardcoded model list or a required Luna or DeepSeek release. A provider-compatible new identifier should be usable without changing GG's application code; model catalogs may assist selection but must not restrict manual entry. Handling different tool and image capabilities still needs validation. This replaces the OpenAI-only initial scope of [ADR-0028](0028-openai-first-provider-boundary.md); user-specific credentials remain separate from the vault as in [ADR-0027](0027-user-specific-ai-provider-configuration.md). The model choice must not change the archive format.

This is a clean implementation restart, not an incremental adaptation of the existing Rust core or desktop app. Small image-format and thumbnail utilities may be reused or reimplemented where useful, but existing-archive import, migration, and bulk enrichment are not first-version requirements. Existing files can still serve as format/size acceptance fixtures. Prior implementation choices are historical context rather than an inherited feature backlog; decisions carried into the replacement should be explicit in the restart documentation.

This replaces the desktop-first and supporting-CLI priorities in [ADR-0030](0030-minimal-cli-over-archive-core.md) and reopens the implementation stack in [ADR-0031](0031-rust-workspace-with-core-cli-and-tauri-app.md). Pi's SDK is the initial integration path; a working prototype must establish its suitability. The exact record format and compatibility with existing items remain implementation questions. The restart does not authorize deleting or migrating the live vault at `/home/cem/Gewolbe`.
